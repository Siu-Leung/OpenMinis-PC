# OpenMinis-PC v1.13.0.27 开发日志

日期：2026-09-05  
内部版本：`1.13.27`  
对外版本：`v1.13.0.27`  
产品：OpenMinis Windows 体验版

## 范围

修复 browser_use 截图“工具成功但聊天没有图片”的数据链问题。本版本按官方移动端的工具快照与消息媒体原则处理：媒体由工具结果结构化传递，不能依赖模型在最终文本里再次正确书写 Markdown URL。

## 官方参考

- iOS：`AssistantBlock.imageFilePath`、`ToolSnapshotItem`、`ToolLiveSheet`
- Android：`AssistantBlock.imageFilePath`、`ToolPreviewThumbnail`、`resolveMdMediaFile`
- 官方共同原则：截图是工具结果的一部分，同时可用于工具预览和聊天消息媒体展示。

## 改动

- browser screenshot 成功后，从结构化工具结果提取 `minis://` 图片 URL。
- URL 进入 Agent 的待附加媒体缓冲，绑定到下一条 assistant 消息。
- 工具循环结束但没有后续文本时，将剩余媒体合并到最近 assistant 消息。
- 前端 assistant turn 聚合时合并并去重 `images` 字段。
- assistant turn 使用现有 `MarkdownImage` 组件直接内嵌显示工具截图，支持加载、放大和保存。
- Edge 截图字节必须成功写入 `/var/minis/attachments` 才返回成功。
- 宿主缓存改由 Rust 直接写入，不再让隔离沙箱执行无效的 Windows 路径 `cp`。
- 截图失败明确返回失败，不再生成 1x1 占位图并冒充真实截图。

## 测试

- 新增 Rust 单元测试：只从成功的 `minis://` 图片工具结果提取媒体 URL；失败结果和普通文本不得被识别为媒体。
- `npm run build` 必须通过。
- GitHub Actions 必须运行 `cargo test --locked` 和完整 Tauri Windows 构建。

## 已知范围

本版本保证截图工具结果自动进入聊天媒体，不宣称已经实现官方的持续 WebView 实时画面。持续浏览器快照、可交互浏览器 tab 池和完整 ToolLiveSheet 状态模型仍在后续版本实现。
