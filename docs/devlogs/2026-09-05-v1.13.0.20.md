# OpenMinis-PC v1.13.0.20 开发日志

日期：2026-09-05  
范围：Windows 端浏览器画中画、工具事件、版本发布流水线

## 背景

对 `OpenMinis-PC` 与原版 `OpenMinis` 的功能实现进行初步对照后，确认聊天发图链路已经接通，但 Windows 版 `browser_use` 目前只实现 `navigate`、`get_text`、`screenshot`。左下角 `Minis Computer` 原先只展示截图，导致文本型浏览器结果虽然已返回，界面仍持续显示加载状态。

详细分析见 [Windows 浏览器、小电视与图片支持审计](../windows-browser-mini-tv-audit.md)。

## 本次修复

### 浏览器与小电视

- 浏览器文本结果可直接显示在 `Minis Computer` 中。
- 每次浏览器工具启动时清理上一轮文本和截图，避免旧预览残留。
- 截图输出仍通过 `minis://attachments/` 路径加载并显示。
- 工具步骤保存真实 URL、Shell 命令或文件路径，浏览器步骤可打开对应页面。

### 工具事件可靠性

- 后端 `tool_end` 增加真实 `success` 状态。
- 前端不再把所有工具调用都标记为成功，失败结果会显示失败状态。
- 失败结果优先展示 `error` / `stderr`，成功结果优先展示 `data` / `stdout` / `message`。
- 工具输出和模型错误改用 Unicode 字符安全截断，避免在中文 UTF-8 字节中间切片导致 Rust panic。

### GitHub Actions

- `npm install` 改为可复现的 `npm ci`。
- npm 缓存键改为 `package-lock.json`。
- 普通 `main` 推送只构建并上传 Artifact，不再自动覆盖固定 Release。
- Tag 推送或手动勾选 `release` 时才执行发布任务。
- 构建任务只授予 `contents: read`；独立发布任务才授予 `contents: write`。
- 发布版本从源码版本推导，校验 `package.json`、`package-lock.json`、`Cargo.toml`、`Cargo.lock`、`tauri.conf.json` 五处一致。
- Tag 必须与源码版本匹配，否则流水线立即失败。
- Release 仅上传三个规范文件：NSIS、MSI、便携 EXE。
- 无构建产物时流水线明确失败，不再静默生成不完整 Release。
